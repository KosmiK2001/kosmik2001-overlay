# max_jail — транзиентный джейл для недоверенного приложения (мессенджер MAX)

Лаунчер `max_jail.sh` запускает приложение так, что оно физически не может
дотянуться до «обхода блокировок» и до лишней информации о машине.
**Система не меняется**: сеть, маски и правила живут только в namespace/на время
процесса и исчезают при выходе. Приложение работает **под текущим пользователем**
(uid 1000, kosmik2001); его данные лежат в настоящих каталогах в его доме —
`~/.config/max`, `~/.local/share/max`, `~/.cache/max` — как у обычного приложения.
Всё ОСТАЛЬНОЕ в доме (`.ssh`, `.gnupg`, документы, чужие дома, Storage) внутри
джейла недоступно.

## Запуск (нужен root)

```sh
sudo ./max_jail.sh --selftest                        # 37 встроенных проверок изоляции
sudo ./max_jail.sh -- /bin/sh                        # шелл внутри джейла
sudo ./max_jail.sh --x11 --dbus -- /usr/share/max/bin/max
sudo ./max_jail.sh --home-mode full -- /usr/bin/max  # ОТЛАДКА: виден ВЕСЬ дом юзера
sudo ./max_jail.sh -d /mnt/backup/max -- /usr/bin/max  # доп. каталог данных -> ~/data
```

Опции: `-n ИМЯ` (netns), `-s CIDR` (подсеть veth), `-d DIR` (доп. каталог в `~/data`),
`--juid N` (uid, default 1000), `--home-dir DIR` (дом, default из passwd),
`--home-mode appdirs|full`, `--x11`, `--dbus`, `--no-mask-etc`, `--selftest`, `--`.

Настройки окружением:
- `MAXJAIL_HOME_BINDS=".config/max .local/share/max .cache/max"` — какие подкаталоги
  дома видны приложению (если оно пишет куда-то ещё — добавьте);
- `MAXJAIL_ETC_EXTRA="foo bar"` — дополнительные пути белого списка `/etc`.

## Требования → как реализовано

| Требование | Механизм |
|---|---|
| Видит ТОЛЬКО default route | свой **network namespace**; внутри только `default via <veth>`, остальное — `unreachable` |
| Не может уйти через VPN (метка 0xa1) | цепочка `VPN` в mangle хоста матчит только `-i brlan0/tap0/tun10`; veth джейла под неё не попадает, таблиц обхода (`youtube.ip`…) в netns нет |
| Никаких прокси/переменных proxy | чистое `env -i`; `/etc/environment`, `/etc/wgetrc`, `/etc/portage/make.conf` отсутствуют (белый список /etc) |
| Локальный DNS и DNS провайдера недоступны | в netns iptables: UDP/TCP 53 разрешён **только** 4 серверам, остальное REJECT; LAN/VPN-сети недоступны |
| DNS только 77.88.8.8 / 8.8.8.8 / 9.9.9.9 / 1.1.1.1 | `/etc/resolv.conf` в джейле содержит только их |
| Не видит чужие процессы | новый **PID namespace** + `/proc` с `hidepid=2` |
| Работает под текущим юзером, но видит только свои каталоги | **mount namespace**: `/home` — tmpfs, в него возвращаются только `~/.config/max`, `~/.local/share/max`, `~/.cache/max` (реальные, на хосте); `.ssh`, документы, чужие дома — не существуют |
| Не видит «обход» в /etc | `/etc` — белый список (openvpn/xray/wireguard/portage/systemd/proxychains/env — исчезают совсем); `/root`, `/var/log`, `/var/tmp`, `/var/lib/dbus`, `/sys` — пусто; `/dev` — минимальный |
| Не трекается по machine-id | `/etc/machine-id` и `/var/lib/dbus/machine-id` — случайные на каждый запуск |
| Никаких привилегий | `capsh --user=max --drop=all` → `CapEff=0`, uid 1000 |
| Не раскрывает юзернеймы хоста | свой минимальный `/etc/passwd` (root + псевдоним `max`); путь дома виден как `/home/<имя>` (необходимо для «работы под текущим юзером») |
| Без изменений системы | netns/veth/маски умирают при выходе (trap); создаются только каталоги данных приложения в доме юзера |

## Проверено (реальный вывод, не теория)

- `--selftest`: **37/37 PASS** — env, маршруты, fwmark-правила, DNS-allowlist,
  недоступность локального/провайдерского/LAN-DNS, egress наружу, недоступность
  прокси и веб-сервера хоста, скрытие процессов, маскировка ФС, machine-id,
  caps, HOME = реальный дом, видимость только каталогов приложения + запись в них.
- `max_recon` внутри джейла видит: **один** `default` (gw 10.200.0.1, dev jv1),
  **ноль** fwmark-правил, **ноль** прокси, в доме — только `.config/.local/.cache`
  с одним подкаталогом приложения, чувствительные пути пусты, процессов — 1.
- Хост после прогонов невредим: `/etc/passwd` цел (74 строки), дом юзера не тронут
  (кроме созданных каталогов приложения, владелец — kosmik2001), лишних
  монтирований и netns нет.

## Что джейл пока НЕ скрывает (и как это закрыть)

1. **`/proc/mounts`** показывает таблицу монтирований хоста (имена дисков, zfs-датасеты)
   — mount-namespace наследует дерево. Полностью убирает только **chroot/pivot_root**
   в подготовленный минимальный rootfs. Делать, когда на руках будет реальный
   пакет MAX (известен список зависимостей — он почти полностью бандловый).
2. **`/usr`, `/bin`, `/lib`**, железо (`/proc/cpuinfo`) — хостовые, видны.
   Тоже закрывается chroot-режимом.
3. Путь дома `/home/kosmik2001_dir` раскрывает имя юзера (компромисс ради
   «работы под текущим юзером»; сам юзернейм в `/etc/passwd` джейла — псевдоним).

## Заметки на будущее

- **MAX — Qt6/QtWebEngine** (не Electron): в пакете нет SUID-sandbox, работает через
  userns (на сервере включён). Если понадобится, раннер может выставить
  `QTWEBENGINE_DISABLE_SANDBOX=1`.
- **GUI**: `--x11` передаёт `DISPLAY`/`XAUTHORITY` (сокет `/tmp/.X11-unix` общий).
- **Несколько джейлов**: подсеть 10.200.0.0/30 по умолчанию — для второго запуска
  `-n имя2 -s 10.201.0.0/30`.
- **Ubuntu**: те же инструменты (ip/iptables/unshare/nsenter/capsh/mount);
  iptables nft-backed, но правила простые — совместимы. Плюс для первого запуска
  `--home-mode full`, чтобы увидеть, какие каталоги пишет приложение.
- Запускать с `sudo`; при выходе `trap` убирает netns/veth даже по Ctrl-C.
